# RAG Intelligence

RAG Intelligence is a full-stack document question-answering application that turns PDF files into grounded, source-backed answers. It extracts and chunks document text, retrieves the most relevant passages with FAISS, and asks Google Gemini to answer using only that retrieved context.

## Features

- Upload and index one or more PDF documents at a time
- Drag-and-drop interface with PDF validation and duplicate prevention
- Semantic search over document chunks with FAISS
- Grounded answers generated by Google Gemini
- Source cards that show the originating file, page number, and retrieved text
- Markdown rendering for generated answers
- Backend health indicator and clear error states
- Recent-question history stored locally in the browser
- Keyboard shortcut: `Ctrl/Cmd + K` focuses the question input
- Responsive React interface built with Tailwind CSS

> [!NOTE]
> Each upload request becomes the active knowledge base. Uploading a new batch rebuilds the FAISS index and replaces the previously indexed batch.

## How It Works

```text
PDF files
   |
   v
PyMuPDF text extraction (page by page)
   |
   v
Recursive text splitting (1,000 characters, 200 overlap)
   |
   v
Sentence Transformers embeddings
   |  falls back to Gemini embeddings if unavailable
   v
Persisted FAISS vector index
   |
   v
Top 4 relevant chunks + user question
   |
   v
Google Gemini answer with source metadata
```

The answer prompt instructs Gemini to use only the retrieved document context. When the context does not contain enough information, the assistant says so instead of inventing an answer.

| Layer | Technology |
| --- | --- |
| Frontend | React 18, Vite, Tailwind CSS, Axios, React Markdown, Lucide React |
| Backend | FastAPI, Uvicorn, Pydantic |

## Prerequisites

- Python 3.10 or newer
- Node.js 18 or newer
- A [Google AI Studio API key](https://aistudio.google.com/app/apikey)

## Local Setup

### 1. Clone the repository

```bash
git clone https://github.com/rishiraj103/rag-project.git
cd rag-project
```

### 2. Configure and run the backend

Create a virtual environment from the project root:

```bash
python -m venv .venv
```

Activate it on Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Or on macOS/Linux:

```bash
source .venv/bin/activate
```

Install the Python dependencies:

```bash
pip install -r backend/requirements.txt
```

Create `backend/.env` and add your API key:

```env
GOOGLE_API_KEY=your_google_ai_studio_api_key
```

Start FastAPI from the backend directory:

```bash
cd backend
uvicorn main:app --reload
```

The backend runs at `http://localhost:8000`. Interactive API documentation is available at `http://localhost:8000/docs`.

### 3. Configure and run the frontend

Open a second terminal from the project root:

```bash
cd frontend
npm install
npm run dev
```

Open `http://localhost:5173`. During development, Vite proxies `/health`, `/upload`, and `/query` requests to the FastAPI server.

## Usage

1. Start both the backend and frontend development servers.
2. Drop one or more PDFs into the upload area, or select them from your computer.
3. Click **Upload & Index** and wait for the indexing confirmation.
4. Enter a question about the active documents.
5. Review the generated answer and expand the source cards to inspect the retrieved passages.

Scanned PDFs without an embedded text layer are not currently supported because the project does not perform OCR.

## API Reference

| Method | Endpoint | Request | Response |
| --- | --- | --- | --- |
| `GET` | `/health` | None | `{ "status": "ok" }` |
| `POST` | `/upload` | Multipart form with one or more `files` | Upload message and processed filenames |
| `POST` | `/query` | `{ "question": "..." }` | Generated answer and retrieved sources |

Example query:

```bash
curl -X POST http://localhost:8000/query \
  -H "Content-Type: application/json" \
  -d '{"question":"What are the main conclusions?"}'
```

## Data and Security Notes

- API keys and environment files are excluded from Git.
- Uploaded PDFs and generated FAISS index files remain local and are excluded from Git.
- Filenames are sanitized before files are written to the `documents` directory.
- CORS currently permits all origins because the application is configured for local development. Restrict allowed origins before deploying publicly.
- FAISS index loading uses pickle-based deserialization. Only load indexes created by this application from a trusted local directory.

## Build the Frontend

```bash
cd frontend
npm run build
```

The production assets are generated in `frontend/dist/`.
